# 制作执行流程：从分析到可复建工程

参考Lemo-Opuscar的导演/技术/风格/demo分工后，为本skill增加的执行约定。没有安装该插件，也没有验证其渲染器在本机可用；这是流程改进，不是已接入它的引擎。

## 将四类内容分开

- **研究证据**：案例ID、PTS、原帧板与观察置信度；不当生产资产。
- **风格规范**：每条作品都成立的材质、空间、颜色逻辑、字级、运动和镜头词汇；不写死苏轼或水滴故事。
- **单片导演方案**：这次要解释的一个变化、开头/转折/结尾、分镜、时序、声音或明确静音。
- **执行工具与例片**：具体引擎、依赖、可运行命令、资源、已渲染结果和验收状态；能复建才叫模板。水滴现阶段是专题程序样片，尚不是可替换选题的通用引擎。

## 制作顺序

1. 把已有用户要求写为项目事实；不要重复询问。只在真正缺少关键选择时集中问一次。用户让直接执行时按已确认条件继续，不增加故事板审批。
2. 在看具体demo代码前，先写这次的沟通目标、两种简短叙事选择及采用理由。十秒只容纳一条主线；复杂环节用全片或明确示意，不让标签替代核心演示。
3. 选择风格与渲染后端。浮雕地表需要可见的法向/明暗、遮挡和相机一致性；密集实体场景优先适当三维或有深度控制的方案。Pillow分层绘制适合某些风格，但不能因为本机方便就默认用它降低目标。
4. 实际代码绘出三个关键帧，其中一个必须是风格最难的镜头；对照原帧板查视觉门。只写分镜、不渲染，不算通过。
5. 共用一条时间轴组织画面事件、文字和声音。无旁白不自动等于无音效；用户指定静音则不强加音乐。静音信息必须靠动作、空间关系和必要文字成立。
6. 检查关键动作的准备/接触/结果与转场的锚点；流体入杯后才升水位、物体接触后才反馈等因果不能由漂亮静帧替代。
7. 渲染、看全时长密采页和关键动作细帧，实际可播放时检查实时速度。自动检测只负责可测问题，不能判定美感或理解程度。
8. 把本轮发现的问题集中修复，再检查修改影响的部分。没有工具能力的听审或实时观看保留未检查，不无限重渲染，也不拿编码正确代替画面通过。

## 最小工程交付

`TREATMENT.md`（导演方案）、`project.json`（时间/文本/事件清单）、源码与明确构建命令、依赖与相对资产路径、成片与poster、`CREDITS.md`（实际使用的来源/字体/资产）、`QA.json`（分项状态）。有字幕再导出字幕文件；没有音轨不伪造音乐或响度报告。

同一风格复用于两个不同主题、保持风格不变量且不需重写大部分引擎后，才把专题样片升级为通用模板。不要为了满足文件数量创建空壳文件。

## 可运行的时间与文字检查

用 `python scripts/check_project.py 项目/project.json --out 项目/时间检查.json` 检查片段边界、覆盖、文本读时和事件依赖。参考[清单格式](project-contract.md)。检查器不读取画面，不知道文本实际上是否按计划绘制，也不判断是否像原片。渲染后必须核对成片，计划正确不等于执行正确。

## 目前优先级

1. **工程后端与组件**：抽出相机/坐标、地形/材质、物件/角色、文字和时间轴；避免每个主题从零拼绘制函数。
2. **风格与主题解耦**：风格只约定视觉语言，故事通过独立数据进入；不能把水路、苏轼一天和场景顺序固化成通用模板。
3. **运行检查与观感检查并列**：先解决可测时序问题，再通过对照图与实时观看评价空间、节奏、理解。
4. **跨AI实跑**：在干净目录、只提供skill和新选题，由另一AI从头构建；此前的读包规划测试不算这项通过。
5. **音轨**：只有具备实际听辨能力后才继续原片声音研究。先前测量不能填补这个缺口。
